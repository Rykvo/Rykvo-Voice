# 模块与 eSIM

设备由 Go 后端自动发现、自动建档，不需要手动添加，没有固定设备数量上限。共享管理器独立于浏览器和功能显示开关运行；同一设备一次采集，多设备最多四路并发。

## 设备路径

| 类型 | 发现与读取 |
| --- | --- |
| EC20 / EC25 / EG25 / 兼容 EG600 | USB 物理设备归组，按接口布局选 AT 口；标准 AT 查询和可用的移远信号查询 |
| EC200A 等移远串口组态 | 移远 VID 发现，AT 读取；不要求 qmi_wwan 绑定 |
| 大疆 4G 模块 | 原厂 2ca3:4006 标识发现，AT 读取，不改 USB 身份 |
| 高通 410 / MHI WWAN | WWAN AT 节点；AT 不可用时使用 qmicli 读取 QMI 状态 |
| USB SIM 读卡器 | PCSC 枚举，独占读卡会话读取 ICCID；无蜂窝信号、无通话能力 |

发现设备不等于其全部业务可用。上述路径需要不同型号/固件实机验证；本版本接入标准 eUICC 管理，不实现短信、通话、SIP、飞行模式切换或数据拨号。没有 AT/QMI/PCSC 可用通道时显示异常，不伪造在线状态。

## 约束

- 监听 Linux uevent，并每 5 秒重新发现；每轮读取结束后至少等待 25 秒再更新设备快照，避免慢设备重叠采集。
- 每设备采集设总时间预算，AT 单命令有独立超时；超时后关闭会话，防止迟到响应串到下一条命令。
- 不自动停其他程序，不修改 USB 模式，自动读取不发送 CFUN、PIN、拨号、短信或配置写入指令；eSIM 写入仅由用户操作触发。
- Linux 串口使用非阻塞 I/O、排他声明和文件锁；占用或权限不足作为异常上报。
- 号码只读 CNUM；SIM 未提供号码时留空，不从 ICCID/IMSI 推算。
- 原始 AT 响应、QMI stderr 不直接回传网页或写日志。
- 设备指纹、路径、标签持久化；动态 SIM/网络状态在内存中。重启后重新确认状态，不把上次在线状态当成本次结果。
- IMEI 优先绑定，其次可靠序列号。序列号升级为 IMEI 时保留 ID 和标签；暂时读不到 IMEI 时不降低已有身份。新蜂窝设备没有可靠身份时等待重试，不按新端口生成重复档案。重复身份显示冲突，不凭相似型号强行匹配。
- 读卡器优先读取读卡器序列号作为身份，缺少序列号时使用读卡器名称。该类设备换口后的身份稳定性需实机验证。

## 标签

默认生成“模块 01”等唯一标签，显示编号与内部 module-数字 ID 保持稳定。标签 1–20 个 Unicode 字符，去除首尾空格；拒绝控制/格式字符。唯一键使用 Unicode NFKC + case folding，因此全角/大小写等价名称视为重复。

数据库唯一约束覆盖离线模块；同一模块保存自身标签合法。清空时分配可用默认标签，另一个模块改名后释放原标签。标签更新与自动命名使用同一个数据库事务锁。

浏览器旧标签只尝试迁入尚未自定义的对应模块，服务器标签优先；冲突或失败不删除原 localStorage 内容。

## 接口

沿用同源 `/api/modules`；域名访问自动挂载为 `/gly/api/modules`。全部经过现有会话验证，写操作继续要求 Origin + CSRF。

- `GET /modules` → `{data:{items:Module[],discoveryIssue:string}}`
- `GET /modules/:moduleId` → `{data:Module}`
- `PATCH /modules/:moduleId`，正文 `{label}` → 更新后的 Module。
- 旧标签迁移可额外传 `{ifUnmodified:true}`；服务器已有自定义标签时返回 409。
- `GET /modules/:moduleId/lines` → `{data:SIM[]}`。
- eSIM 下载、线路启停、卡内昵称和删除沿用预留接口；详情见前端 BACKEND.md。

Module 保留 `{id,name,label,number,status,signal,sims}`，增加 `managed`、`labelCustom`、`kind`、`hardware`、`issue` 和 `capabilities`。`status` 仍为 online/offline/error；控制通道可响应不代表驻网成功。`signal` 增加 cellular，真实运营商/制式/信号指标放在 hardware 中。未知 RSSI 等指标为 null。

普通 SIM 带 `readOnly:true`。eSIM 配置 ID 由 EID + ICCID 生成，不依赖数组下标。capabilities 中 sms/calls/lineControl 为 false；esim 由真实探测和任务占用状态决定。

`capabilities.esimDownload` 表示已确认 eUICC 管理能力，与任务忙闲分开：普通 SIM、离线或未识别卡不显示下载入口；支持卡在任务执行期间保留入口但禁用。最终下载仍取决于卡内空间、激活码和运营商校验。

## 网络状态

模块自行自动搜网与注册，页面只读取运营商、注册状态和信号。手动搜网、选网接口及执行代码已移除；旧选网任务保留数据库记录，不恢复到页面。移除功能不会自动改写设备原有模式。卡片通道读取失败显示实际错误，不持续显示读取中。

数据连接及漫游控制仍待接入，需要管理 APN、数据上下文和漫游许可。

### Wi-Fi 通话

沿用线路 PATCH：`{requestId,wifiCalling:true|false}`，返回更新后的 Module；页面复用 SIM 详情中的 Wi-Fi 通话页。模块包含 `wifi:{enabled,registered,state,issue}`，能力通过 `capabilities.wifiCalling` 独立判断，不依赖是否为 eSIM。

- 当前接入 EC20（2c7c:0125）的次 AT 口，避免与已占用主 AT 口的 ModemManager 争抢回复。启动前核对 USB 世代、IMEI 指纹和当前 ICCID；蜂窝数据仍启用时不切换射频。
- 开启联动 CFUN=4，回读确认后进行 USIM AKA、IKEv2/ePDG 和受保护的 IMS REGISTER。开关表示用户配置，只有收到并验证 IMS 200 后才显示“已连接”。
- UDP 注册请求和响应使用各自协商的 ESP 安全关联，接收端为 UE server 端口；校验 MAC、重放窗口、地址、端口、Call-ID、CSeq、Via branch，保留证书和对端认证。
- 一个事件循环维护 NAT 心跳、IKE 存活检查、IMS 续期和当前卡校验。可重试网络故障有限退避，鉴权拒绝、未知清理结果不反复重试，也不触发模块重启。
- 复用单模块互斥。eSIM 操作先停止 Wi-Fi 会话，再等待注销、逻辑通道和射频清理；清理结果不明时阻止写卡。关闭功能恢复该模块蜂窝射频；维护探针恢复进入测试前的射频状态。
- 用户配置按模块和 ICCID 持久化；重新插入需重新核实身份。旧卡的“已连接”状态不沿用到新卡。账号、会话、配置及其他模块不重置。
- 用户态 UDP/ESP 不增加系统网络权限、不建立 TUN、不改服务器路由。密钥仅驻留内存，不写日志、数据库或安装包。

本轮接通的是 **Wi-Fi 通话注册与维持连接**。02 实卡已验证注册、续期、心跳、注销；不代表所有运营商均兼容。当前为 UDP + EAP-AKA / AKAv1-MD5；TCP、AKA′、ISIM 特定运营商配置、完整呼叫/音频和 IMS 短信业务仍待接入。未实现的来电或短信请求不返回虚假成功。

参考 VoCat 提交 `484cd236dd543e2ba142cf1da2c5808ee8e89a6e` 的流程与协议行为，未复制其受限实现。`-hardware-wifi-check` 只读前置检查；`-hardware-wifi-run` 为有界维护测试，最长保持 600 秒并自动清理，不在普通接口开放。

## 运行环境

继续使用低权限 rykvo_voice 账号。安装器安装 QMI 工具和 PCSC 运行库、驱动，通过应用专用 udev / polkit 规则授予所需设备访问权；不把 Web 服务改为 root。

PCSC 使用 purego 动态加载系统 libpcsclite，编译仍为 CGO_ENABLED=0。原生驱动调用放在本程序受超时限制的子进程中，坏读卡器不会长期占住主进程采集线程。qmicli 使用参数数组执行、限制时间与输出大小，不经 shell 拼接。

程序卸载同步删除本应用的设备访问规则，保留共用软件包。真实全新安装/更新/卸载和各型号实机联调另行验证；不对现有虚拟机自动执行这些操作。

## 9eSIM / eUICC

复用固定提交的 MIT `euicc-go` 协议库，未复制 VoCat 受限源码。生产 CI 根证书来自同一依赖的 production bundle，保留系统 Web PKI，不载入其测试根证书。

EC20 使用 AT+CSIM 管理独立逻辑通道，不依赖部分固件缺失的 CCHO。PCSC 与 QMI UIM 使用同一 LPA 逻辑；QMI 通过代理访问默认物理卡槽 1，不自动切换卡槽或射频。9eSIM 等标准 ISD-R 卡片按能力探测，不仅凭品牌判断支持。

实现 EID/配置列表、下载、启用、停用、卡内昵称、删除和通知重试。9eSIM 按卡内实际配置数量列出全部配置，包含未启用项，不预设数量或填充占位项；普通运营商 SIM 只返回当前卡的一条记录。手机号仅在实际可读取且对应当前配置时显示，其余使用卡内标签，不复制当前号码到其他配置。使用每设备事务锁，与后台采集互斥；多个设备可并行处理，最多四个写任务并发，没有设备数量配额。删除需要网页确认且仅处理停用、策略允许的配置，不提供整卡重置入口。写操作校验 EID 和存在的 ICCID，操作后重新读卡核实；通道重置后结果不明时显示待核实，不自动重复下载或删除。

任务状态持久化，但激活码、确认码和配置包只在内存/匿名管道中传递；底层原始调试日志关闭。子进程隔离原生驱动故障、限制总执行时间。运营商 HTTPS 保持证书验证，拒绝私网/本机目标和重定向，限制响应大小，通知发送成功后才移除卡内记录。

真实 9eSIM 芯片版本、EC20 固件、空配置卡片、切换后的驻网和各 QMI/PCSC 实机仍需联调。代码接入不等于全部硬件和运营商验证通过。

无卡状态只接受明确的 AT SIM not inserted / CME 10 或 QMI card absent。AT 返回普通 ERROR 时用 QMI 核实，已确认空槽不探测 eSIM；超时、SIM failure 和未知状态不当成无卡。列表和详情统一显示“无 SIM 卡”，模块在线与卡片驻网状态分别表示。

## 故障恢复（1.1.8 起，1.1.9 实机部署）

- 仅已在本次服务运行中读到 IMEI、且 USB 端点及世代未变化的 EC20（2c7c:0125）。从启动就未能核实身份的设备不自动复位。
- 连续通信超时至少 3 次、持续 90 秒后尝试 QMI operating-mode reset。仅 eSIM 操作失败、未插卡、无服务、注册被拒绝、权限错误或端口占用不触发。
- 复用现有采集、单设备互斥与任务状态，不新增轮询。写卡任务期间不重启；恢复后留 90 秒重新枚举，再读取真实状态。
- 全局恢复间隔 90 秒，同一模块间隔 10 分钟、每小时最多 2 次。先持久化尝试再发送，服务重启不清空限制。
- 指令超时或结果不明时停止该模块的自动重试；待实际读取恢复后解除。收到指令确认不等于恢复，只有真实通信正常才记录 recovered。
- 特权本机助手仅执行固定命令，复核设备节点、qmi_wwan 驱动、EC20 型号、USB 路径和 busnum/devnum。不复位 Hub、不重启整机、不改卡内配置、不自动停止其他管理服务。
- 页面仅在恢复期间显示“正在恢复”，不添加长期成功提示。日志仅记录模块编号与阶段，不记录号码、IMEI、ICCID 或激活码。

自动恢复是故障处理，不是供电、USB 直通或并发问题已根治的证明。当前真实设备验证仍以 deploy/VALIDATION.md 为准。
