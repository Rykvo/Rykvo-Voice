# 打包与更新

## 使用
通用 → 软件更新 → 上传 `.rvu` → 校验 → 确认更新。

- 上传按 1 MiB 分块，进度只计算主机确认的字节。短暂断线自动重试，重新选择同一文件可续传。
- 上传不执行安装；只有管理员确认后才安装，关闭页面不取消已提交的安装。
- 使用原有管理员登录、同源及 CSRF 校验。网页不接收、不返回解密密钥。
- 先核验签名元数据再接收正文，完整密文验签和 GCM 认证通过后才解包；安装前再次验证。
- 临时文件位于 root 私有目录，不作为网页资源；仅一个活动上传，限制大小、空间与解压路径。上传闲置超过 24 小时，在下次操作时清理；处理结束清理临时包。
- 更新先排空任务、备份、迁移和原子切换；健康检查失败恢复程序，不覆盖新增业务数据。
- 健康检查通过后保留最近两份恢复备份及对应程序；失败不轮换备份。
- 不卸载在用驱动、不替换网络管理器、不改默认路由，保留业务 Tunnel。
- UPDATE_EPOCH=2，同通道允许跳过中间版本的完整向前升级，禁止降级，同版本允许修复重装；发布包包含完整程序与累计迁移。

## 跨版本兼容：修改代码前必读

目标：从加密升级基线 **新发布线 1.1.0** 起，任一已发布版本可直接升级到更高版本，无需逐个安装中间包。全量程序不等于数据已兼容，下面两部分必须同时成立。

1. **旧升级器能读新包。** `RYKVOU15`、签名域、头尾结构、外层清单 schema 2、内层 schema 1、UPDATE_EPOCH=2 是协议，不随产品版本号修改。保留基线支持的目录、文件类型与大小上限；新增强制字段或提高限制前，必须证明旧升级器仍接受。
2. **完整目标程序。** 每包带齐 amd64/arm64 程序、页面、运行脚本、服务定义、依赖与许可证，不借用上个版本残留文件，不把差分包当全量包。
3. **累计数据迁移。** 目标程序包含从所有支持旧结构到目标结构的完整路径，不能只处理上一版。迁移按顺序、可重入，处理缺列、旧默认值和历史配置；失败后可恢复并重试。已发布迁移保留语义，不为清理代码直接删除或改写。
4. **保留业务。** 账号、会话、配置、模块与 SIM 对应关系、短信记录、SIP 和 Tunnel 均需保留。改名、拆表、字段收紧先转换旧数据；迁移不默认重置、不静默丢弃旧值。
5. **安装与恢复兼容。** 保留排空、快照、原子切换、健康检查、失败恢复及旧版维护接口；结构变更必须考虑旧程序恢复后能否读取迁移后的数据。不得用覆盖业务数据库的方式假装回滚成功。
6. **密钥稳定。** 本正式发布线内复用统一 AES 密钥和签名信任链，每包使用新 nonce。发版不重新生成密钥；轮换方案须兼容所有支持的旧主机，不能让用户逐台输密钥或安装过渡包。
7. **版本独立。** VERSION 只表示应用版本；包名、内外清单与程序版本一致。向前跳版本、同版修复、拒绝降级三条规则保持不变。
8. **构建阻断。** `deploy/compatibility.py` 固定使用 `tests/fixtures/updater-1.1.0` 中的初版升级器与 SHA-256 清单验证新 RVU 的两个架构，不跟随 main 替换基线。失败必须修兼容代码，不删除检查、不要求用户补装中间版。

本仓库从 1.1.0 开始正式发布，使用独立签名与加密密钥。旧测试发布线不作为升级来源，由维护者重新安装，不放宽降级或验签保护。后续版本保留从本发布线 1.1.0 起直接跨版本升级的契约。

## 密钥
- 签名：Ed25519 私钥只由发布方保管，Actions Secret 为 `RYKVO_UPDATE_SIGNING_KEY`（32 字节十六进制）。仓库和主机仅保存 `deploy/update-signing.pub` 公钥。
- 加密：AES-256-GCM，独立随机 nonce；统一密钥为 Actions Secret `RYKVO_UPDATE_ENCRYPTION_KEY`（32 字节十六进制）。主机仅在 `/etc/rykvo-voice/update.key` 保存，root:root、0600，目录 0700。
- 首次安装自动下载并验证签名安装引导文件 `install.rvk`，把统一密钥写入 root 私有目录，无需逐台输入。已有合法密钥直接复用；损坏或不匹配时停止，不覆盖。后续正常上传加密包。
- 签名私钥不得进入源码、发布附件、主机、网页或日志。统一解密密钥仅额外通过签名安装引导文件提供，以满足免配置批量安装；引导文件不是加密保险箱，下载者可以恢复统一解密密钥，这是已选择的部署取舍。网页接口不返回密钥；安装时不输出密钥。
- 本功能保护更新包，不保证对主机 root 保密；公开源码和旧明文发布不因加密而自动撤回。

## 发布
1. 同步 VERSION、页面资源版本和 RELEASE_NOTES.md，完成 TESTING.md 中的回归。
2. 从干净提交构建：构建机安装 `zopfli`，配置两个发布 Secret，执行 `python3 deploy/build.py --output dist`。
3. 双架构运行包只在私有临时目录组装。发布产物为 `RykvoVoice.版本.rvu`、`release.json` 和 `install.rvk`；不包含明文程序 ZIP、签名私钥或业务数据。
4. 核对版本、编译提交、签名、摘要与架构，运行包保留许可证。
5. 推送源码和标签不自动打包。手动工作流用于预检；Releases 发布 `release/v版本`（Target main）后触发完整测试和构建，成功后附加加密产物，不覆盖旧附件或标签。
6. 发布与实机测试分别记录。明确要求才升级主机。

压缩优化仅在构建机执行，仍是标准 gzip；逐字节验证解压内容一致，包变大则保留原编码。主机不安装压缩器，不在启动时解压程序。
